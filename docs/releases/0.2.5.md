## What's changed in 0.2.5

One change, and it's the one the DRM story has been building toward: the engine binary is no longer renamed.

- **firefox.exe stays firefox.exe, and seijaku.exe is now a small launcher.** The launcher starts firefox.exe with the shell and forwards whatever arguments it receives, so shortcuts, clicked links, and the post-update restart all work exactly as before. Double-clicking seijaku.exe on its own also works — the launcher supplies the shell's location when no -app argument is given.
- Why: 0.2.4 proved Widevine downloads fine on demand, but protected video still wouldn't play under the renamed binary. Breached releases have always kept firefox.exe unrenamed for exactly this reason — sites that only play protected video in browsers whose engine Google has certified. This build adopts that same layout.
- What changes for you: Task Manager and process listings will show firefox.exe again instead of seijaku.exe — that's the trade-off, and it's the price of certified playback. The taskbar button, grouping, and seal icon are unchanged (they come from the window and the shortcuts, not the binary name). Everything else — tabs, downloads, settings, the Widevine button itself — is untouched.
- The test: install, open a DRM tester, and video must actually play — not just download. If it plays, the DRM story is closed.

Install with `SeijakuSetup-0.2.5.exe` (no admin, no Firefox first), or unzip the portable build and run `Seijaku.bat`. The files aren't code-signed yet, so Windows SmartScreen may say "Windows protected your PC" — choose More info, then Run anyway.

Honest caveat: the launcher itself is new code (ported closely from Breached's proven launcher, including its compile step), and like everything else here it hasn't run on Windows yet. If the release workflow's compile step fails, that will show in Actions before any installer is published.
