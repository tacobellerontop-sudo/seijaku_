## What's changed in 0.2.4

One thing, and it's the one that matters: protected video finally has a way to actually get Widevine.

- **A "Protected video" section in Settings.** It has a Download Widevine button and a status line. Press it and the browser asks Mozilla's update server for Widevine directly (about 10 MB) instead of waiting for the automatic check — which, as 0.2.1 through 0.2.3 proved, never runs on its own in this shell. Status goes Not installed → Downloading… → Ready, with the version shown. If the server offers nothing, it says so plainly instead of pretending.
- Why this exists: 0.2.1 fixed the channel, 0.2.3 stated every download setting and stamped the real engine version, and a fresh profile still got nothing — the automatic download path simply doesn't deliver here. This button is the same mechanism Breached's DRM mod uses (Gecko's own installer, same Mozilla server), built into Seijaku natively, no mod system involved.
- After it says Ready, pages that already asked for protected video need a reload — then a DRM tester should pass. If the button instead reports that the server didn't offer Widevine, that's a new, precise diagnostic: the manifest request itself is failing, not the scheduling around it.

Install with `SeijakuSetup-0.2.4.exe` (no admin, no Firefox first), or unzip the portable build and run `Seijaku.bat`. The files aren't code-signed yet, so Windows SmartScreen may say "Windows protected your PC" — choose More info, then Run anyway.

Honest caveat: like everything DRM-related so far, the button flow itself hasn't run on Windows yet. The test is: Settings → Download Widevine → Ready with a version → DRM tester passes after a reload. One thing this still can't prove in advance: whether the downloaded CDM loads under the renamed seijaku.exe — the tester passing is what settles that.
