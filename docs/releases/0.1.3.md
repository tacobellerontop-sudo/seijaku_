## What's fixed in 0.1.3

- **You can reopen it again.** 0.1.2 broke that: the installer shortcuts started the renamed engine with no arguments, and a bare engine with no front end left shows nothing. The post-install launch worked because it did pass `-app`, which is why the first run was fine and reopening failed. Shortcuts now pass `-app` like everything else does.
- **Taskbar icon, second attempt.** The 0.1.2 icon file was verified inside the released zip, in the right place, yet the taskbar still showed Firefox — so file placement alone isn't the lever. This build also puts the icon under the content package and names it in the window's `icon` attribute, covering the other lookup path Gecko might use. If the taskbar still shows Firefox after this, the remaining suspect is Windows grouping the window under Firefox's AppUserModelID, and that will need a different fix — please check the Details tab in Task Manager (Image Name should already be `seijaku.exe`) and whether the portable zip's taskbar button differs, and report back before another blind attempt.

Install with `SeijakuSetup-0.1.3.exe` (no admin, no Firefox first), or unzip the portable build and run `Seijaku.bat`. The files aren't code-signed yet, so Windows SmartScreen may say "Windows protected your PC" — choose More info, then Run anyway.
