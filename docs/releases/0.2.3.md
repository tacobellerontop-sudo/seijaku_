## What's changed in 0.2.3

This one finishes the downloads story and fixes two things users tripped over, plus two small DRM bets.

- **A real download manager.** The downloads page (Ctrl+J) now has search, speed and time remaining on active downloads, pause and resume (pause keeps the partial file; resume restarts it where it stopped), retry for failed downloads, restart, clear finished, and a history that survives restarts — the engine's own list turned out to be session-only, so finished downloads are recorded in your profile data file. Removing an unfinished download also drops its partial file; removing a finished one never deletes the file itself.
- **A downloads button in the strip.** It shows the first active download's percentage live (↓ 47%), and opens the manager on click. When nothing downloads it's a plain arrow.
- **Strip buttons stay on the right.** The actions group is pinned to the right edge no matter how few tabs are open — before, the drag space after the actions ate it and the buttons drifted toward the middle. Side strips keep their actions at the bottom.
- **Settings dropdowns work now.** This was a real bug, not a styling issue: a native `<select>`'s popup never opens in these chrome-hosted pages, because the host window isn't a XUL window and the popup has no proper parent chain — every settings dropdown failed the same way. Pages now use a lightweight in-page stand-in (a button with an in-flow list) while the native select stays underneath as the value holder, so every existing setting binding works unchanged. Same fix on the bookmarks and PDF pages.
- **Download folder setting.** Settings now has a download folder (with a Choose folder button) and an ask-where-to-save toggle. Empty means the system Downloads folder; changing it affects new downloads only.
- **Two DRM bets, both zero-risk.** The Widevine download settings are now stated explicitly (download URL, visible, autoupdate), and the packager stamps the engine's real version and build ID into the packaged app instead of the repo's hardcoded values, so the download request advertises the engine actually shipping. Neither changes behaviour on its own if the download was already working — they remove two unknowns from the diagnosis. The 24-hour throttle explanation from the 0.2.1 investigation still stands: if a profile checked within the last day, the retry waits. If Widevine still fails after this, check for a gmp-widevinecdm folder in the profile: present means it downloaded but won't load (the renamed-binary question), absent means the download still never happened.

Install with `SeijakuSetup-0.2.3.exe` (no admin, no Firefox first), or unzip the portable build and run `Seijaku.bat`. The files aren't code-signed yet, so Windows SmartScreen may say "Windows protected your PC" — choose More info, then Run anyway.

Honest caveat: like everything since 0.2.1, none of this has run on Windows yet. Test the manager first (a real download: button percentage, pause/resume, retry, history surviving a restart), then the settings dropdowns on every settings control, the strip buttons with one tab open, and the download folder setting. The DRM items need the same test as before: a fresh profile, a DRM tester, and the gmp-widevinecdm folder check.
