# Seijaku 0.2.10

A fix-up and performance release. No new features. Most of these bugs came from one cause: the shell never started the engine's own page helpers.

## Fixed: web pages missing basic browser behaviour

Firefox's front end registers the engine's page actors, the small helpers that connect a web page to the window around it. The packager drops that front end, so Seijaku never had them. Without them, `<select>` dropdowns on websites didn't open, video controls didn't appear, Ctrl+F found nothing, and the tab speaker mark never showed. The shell now registers the engine's toolkit set at startup, the same way Firefox and GeckoView do.

## Fixed: find, zoom and reader view on websites

Web pages run in their own content process, so the chrome window can't reach their document directly. Find, zoom and reader view all tried to, so on any real website they quietly did nothing.

- **Find (Ctrl+F)** now uses the browser's own finder, which works across processes. Enter finds the next match, Shift+Enter the previous one, and Esc clears the selection and returns focus to the page.
- **Zoom (Ctrl+= / Ctrl+- / Ctrl+0)** now sets the page's zoom through its browsing context. That works for every page, whichever process it runs in.
- **Reader view** now extracts the article inside the page's process, using Firefox's own Readability. The extracted HTML is sanitised before it reaches the privileged reader page, so scripts, event handlers and forms are removed.

## Fixed: site permission prompts, camera, microphone and video calls

- **Notification and other site prompts never appeared.** The prompt was registered with a `component` line in `chrome.manifest`, and current Gecko no longer reads those lines, so every request was silently denied. The prompt is now registered when the browser starts.
- **Camera and microphone requests waited forever.** Pages ask for these through a separate engine path that Firefox's front end answers, and nothing answered it in Seijaku. A small actor now answers it: it uses the first camera and microphone, asks you through the same prompt, and remembers your choice if you tick the box. Screen sharing isn't offered and is refused rather than left hanging.
- **Video calls hung before connecting.** Every `RTCPeerConnection` offer waited for the browser's go-ahead, which never came. It is now given straight away, as Firefox does, with the camera and microphone prompt as the real gate.

## Fixed: bookmarks and history could be lost

- The data file was rewritten in place. A crash or power cut during a write could leave a half-written file, and the next start would replace it with an empty one. Writes now go to a temporary file first and are then moved into place. If the file is ever unreadable, a copy is kept as `seijaku-data.json.damaged` before anything overwrites it.
- A bookmark or history entry made while the file was still loading at startup was dropped. It could even replace the whole file for a moment. Early changes are now merged into the loaded data.
- A private window loaded its own copy of the bookmarks file. Bookmarking from it overwrote any history the main window had recorded since. It now shares the main window's live data.

## Faster: far less disk writing

Each page load reports its address, title and finish separately, and each report rewrote the whole history file (up to 1000 entries) and the session file. Writes are now batched, with at most one per second, and anything pending is written when the window closes.

## Smaller fixes

- The downloads page rebuilt every row twice a second while a download ran. A click on Pause or Cancel could land on a button that had just been replaced. Rows are now rebuilt only when the list changes, and progress updates the text in place. The page also stops polling while its tab is in the background.
- Closed windows kept receiving settings changes, because their preference listener was never removed.
- Changing any setting re-applied the theme. Now only theme settings do.
- Address bar suggestions and the command palette no longer copy the whole history on every keystroke.
- The password manager is turned off (`signon.rememberSignons`). Seijaku has no UI to save or fill logins.

## Tested on Windows

A new Smoke test workflow builds the release exactly as the Release workflow does, then starts it headless on a GitHub Windows runner. It passes all 10 checks on the current Firefox build:

- web pages load in their own content process
- the engine's page actors are registered
- find locates and misses text correctly
- zoom changes and resets
- reader view extracts the article and strips scripts
- the camera and microphone prompt grants access, and a denial reaches the page
- a peer connection offer completes
- the notification prompt grants permission
- history, bookmarks and the session are saved atomically

## Still to check by hand on Windows

These need a real screen, a real device or a real account.

- On a site with a `<select>` (any sign-up form), the dropdown opens and picks a value.
- A `<video controls>` page shows its controls.
- A real webcam call (for example a WebRTC test page or a video call site) shows the prompt and the video.
- In-app update from 0.2.9, and DRM video, behave as before.
- A tab playing sound shows the speaker mark, and clicking the mark mutes it.
- Bookmark something in a private window, then check that the main window's history is still intact.
